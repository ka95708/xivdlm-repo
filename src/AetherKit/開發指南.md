# AetherKit 開發指南

新增或修改功能前先看這份。目的是讓每個功能的分類、介面、用詞、做法都一致。
遊戲改版後要先檢查的東西另外列在 [改版檢查清單.md](改版檢查清單.md)。

## 1. 架構

| 東西 | 位置 | 做什麼 |
|---|---|---|
| 插件本體 | `Plugin.cs` | 設定檔、指令（`/aetherkit`、`/ak`）、模組清單與開關、共用按鈕列 |
| 模組 | `Modules/*Module.cs`，實作 `IModule` | 一個功能一個模組，左邊清單的一項 |
| 執行邏輯 | `Game/` | 模組背後真正做事的類別（例如 `FateFarmer`、`RetainerWork`） |
| 小功能 | `Tweaks/`，繼承 `Tweak`（清單型用 `LoopTweak`） | 全部收在「小功能」模組（側邊欄自己一區，一個分組一頁），各自開關 |
| 核心能力 | `Core/`，繼承 `Capability` | 對話推進、過場跳過、自動確認、交道具、修理……功能用「借用」的 |
| 設定 | `Configuration.cs`、`Model.cs`、各功能的 `*Config.cs` | 存成一個 JSON；新屬性給預設值就好，不用升版本 |

共用工具：

| 工具 | 用途 |
|---|---|
| `Core/Addons.cs` | 找遊戲視窗、按按鈕、送 callback、讀視窗文字、點選項清單（SelectString）、讀遊戲文字表（`Addons.Text(row)`） |
| `Core/Routine.cs` | 一步一步等條件的流程（C# 迭代器），自動流程都用這個寫 |
| `Core/OperationLock.cs` | 操作鎖：會動角色、點視窗的流程同時只能一個 |
| `Core/FeatureLog.cs` | 每個功能自己的 log 檔：`logs/名稱-日期.log`，留 7 天 |
| `Core/DutyFinderSettings.cs` | 讀寫任務搜尋器選項 |
| `Tweaks/AddonBar.cs` | 貼在遊戲視窗旁的按鈕列（`plugin.AddonBar`），模組和小功能共用 |
| `Game/Navmesh.cs` | vnavmesh 的 IPC |
| `UI/ModuleUi.cs` | 模組頁的版面零件（見第 3 節） |
| `UI/Paint.cs`、`UI/Icons.cs` | 繪圖、遊戲圖示 |

## 2. 分類：放在哪一組

| 分類 | 什麼樣的功能 | 開關 | 左邊清單的點 | 例子 |
|---|---|---|---|---|
| **自動流程**（`ModuleGroup.Automation`） | 要按「開始」才跑、會跑一段時間、會自己移動角色或排本，跑完或按「停止」就結束 | 沒有啟用開關（一直開著） | 綠 = 正在執行 | 自動Fate、青魔教皇 |
| **功能**（`ModuleGroup.Feature`，預設） | 開著就一直在：畫東西、加按鈕、自動處理某個遊戲視窗 | 有「啟用」 | 綠 = 啟用 | 工具列、持有狀況、插件訊息、自動雇員 |
| **小功能**（`Tweak`） | 掛在某一個遊戲視窗或事件上的小改動，不需要自己的一整頁 | 在分組頁或搜尋頁各自開關 | 分組的點：亮 = 這組有開著的 | 一鍵分解、任務搜尋器快速設定 |

判斷順序：
1. 需要「開始／停止」、會長時間自己操作角色 → 自動流程。
2. 符合下面任一項 → 功能（側邊欄自己一頁）；都不符合 → 小功能。

| 看這幾點 | 側邊欄（功能） | 小功能 |
|---|---|---|
| 掛在幾個遊戲視窗上 | 好幾個視窗，彼此有關聯（雇員清單＋出售清單＋價格視窗） | 一個視窗或一個事件 |
| 設定有多少 | 要分段、要分頁，或有清單類設定（區域、名單） | 開關加幾個選項，在清單裡展開幾行就講完 |
| 有沒有要看的狀態 | 有（狀態、進度、統計、相依插件） | 沒有，開了就生效 |
| 自己的視窗 | 有，而且是主要使用方式（價格表、訊息紀錄） | 沒有，或只是附屬的小視窗 |
| 指令 | 有自己的 `/aetherkit xxx` | 用 `/aetherkit tweak 名稱` 開關就夠 |

拿不定時先做成小功能；之後設定變多、需要狀態再搬到側邊欄（搬的時候 Id 不變，設定才接得上）。

小功能的「運作方式」標籤：`按鈕`（在遊戲視窗上多按鈕）、`自動`（開著就自動做）、`視窗`（自己的視窗）。

## 3. 介面

### 側邊欄

由上到下：**自動流程**、**功能**、**小功能**（第一項「搜尋」，下面一個分組一項），分隔線下面是共用頁（核心能力、主題、快捷鍵列表、匯入匯出）。

- 自動流程、功能：一個模組一項，前面的點見第 2 節。
- 小功能：「搜尋」頁只列搜尋到的（沒輸入時不列）；分組頁列該組全部，前面的點亮 = 這組有開著的。新的小功能選一個 `TweakGroup` 就會出現在對應分組；要新增分組就加在 `TweakGroup` 列舉並在 `Name()` 給中文名。

### 模組頁

管理視窗會先畫「名稱」＋一句「說明」（`IModule.Description`），功能類再畫「啟用」。接著是模組的 `DrawHeader`，最後是分頁。

`DrawHeader` 一律用 `ModuleUi` 組，順序固定：

1. **控制列**：`ModuleUi.Action("開始"／"停止"／"開啟訊息紀錄")`，後面接 `ModuleUi.Command("/aetherkit xxx")`。沒有主要按鈕就省略。
2. **狀態**：`ModuleUi.Status(狀態)`，下面每行一個 `ModuleUi.Detail("標題", "內容")`（進度、已執行、目前目標……）。
3. **需要的東西**：`ModuleUi.Borrows("對話推進、修理")`（執行時借用的核心能力，自帶「核心能力設定」按鈕）、`ModuleUi.Dependencies(...)`（相依插件）。

分頁（`SettingsTabs`）：
- 第一個分頁一律叫 **「設定」**。
- 分頁裡用 `ModuleUi.Section("標題")` 分段，段裡的補充說明用 `ModuleUi.Note(...)`。
- log 不在功能自己的頁面放區塊或按鈕；開 log 資料夾統一在核心能力頁的 Log 一段。

範例（自動流程）：

```csharp
public void DrawHeader()
{
    if (ModuleUi.Action(Runner.Running ? "停止" : "開始")) Runner.Toggle();
    ModuleUi.Command("/aetherkit xxx");

    ModuleUi.Status(Runner.Status);
    if (Runner.Running) ModuleUi.Detail("進度", $"第 {n} / {total} 輪");

    ModuleUi.Borrows("自動確認、修理");
}
```

### 遊戲視窗旁的按鈕

- 一律用共用按鈕列：模組在 `AfterWindows` 裡呼叫 `plugin.AddonBar.Button(視窗名稱, 文字, 動作)`，小功能覆寫 `AddButtons`。不要自己畫按鈕。
- 按鈕超過 3 個會自動收成選單，所以一個視窗上的按鈕盡量少。
- 執行中只顯示一個「停止（正在做的事）」。

### 在遊戲視窗裡加東西

要「跟遊戲 UI 一模一樣」時（例如更多貨幣顯示、持有狀況），才在遊戲視窗裡建原生節點：
- 優先改遊戲要顯示的文字（字串陣列，例如物品資訊框的名稱），不夠才建節點。
- 建的節點自己記住、自己拆；拆的時候釋放自己配的記憶體，借用遊戲的（例如數字圖片）不釋放。
- 遊戲重建視窗或開 HUD 版面配置時要先拆或忘掉，別碰已經不存在的視窗。
- 一律在遊戲執行緒做，列進改版檢查清單。

### 蓋在遊戲視窗上的自己的視窗

例如自動雇員的價格表：跟著遊戲視窗的位置畫，必要時把底下的遊戲視窗藏起來（避免滑鼠觸發底下的資訊框），關掉時一定要還原，並列進改版檢查清單。

## 4. 用詞

| 情境 | 用這個 | 不要用 |
|---|---|---|
| 自動流程的主要按鈕 | 開始／停止 | 啟動、執行、結束 |
| 功能、小功能的開關 | 啟用／停用（模組）、開啟／關閉（小功能） | — |
| 狀態 | 「狀態：…」，句子簡短，例如「前往第一個點」「已停止：完成」 | — |
| 指令提示 | 「指令：/aetherkit xxx」（用完整的 `/aetherkit`，不用 `/ak`） | 「也可以輸入…」 |
| 補充說明 | 寫「會怎樣」，不寫實作細節；一兩句 | — |
| 遊戲名詞 | 照台服遊戲內的叫法（Gil管理、修改價格、任務搜尋器…），從遊戲文字表讀 | 自己翻的名稱 |
| 功能名稱 | 中文名給人看（自動Fate、青魔教皇、自動雇員），英文名用在類別與 Id（AutoFate、BlueMageVaultFarm） | 中英混用在畫面上 |

功能名稱一旦發布，模組的 `Id`、小功能的 `Id` 不要再改（設定檔用它記開關）。

## 5. 做法

### 優先順序

1. 透過遊戲介面操作：點按鈕（`Addons.ClickButton`）、送 callback（`Addons.Fire`）、點選項（`Addons.ClickSelectString`）、用技能（`ActionManager.UseAction`，跟按快捷列一樣）。
2. 沒有可行的介面做法時，才直接呼叫遊戲函式或改記憶體。這時：
   - 程式碼那一行附近加標記 `// [改記憶體]`、`// [遊戲函式]` 或 `// [Hook]`；
   - 加進 [改版檢查清單.md](改版檢查清單.md)，寫清楚改版後怎麼確認。
3. 不送封包、不直接改角色位置（瞬移）。

### 遊戲文字

台服的選項、提示文字不要寫死猜的字，從遊戲文字表讀：`Addons.Text(row)`（Addon 表）、Lumina 的 `LogMessage` 等。row 編號寫在註解裡。
畫面上的文字常夾著控制碼（顏色等），要當遊戲文字解析（`SeString.Parse(...).TextValue`），不能直接轉字串。

### 執行緒

- 碰遊戲的東西（按按鈕、用技能、改設定）一律在遊戲執行緒：模組的 Update／`Services.Framework.Update`。
- ImGui 的按鈕按下後，要動遊戲的事用 `Services.Framework.RunOnFrameworkThread(...)` 丟回遊戲執行緒。

### 自動流程

- 用 `Routine` 寫成一步一步：`yield return Routine.Until(條件, 秒數)`、`Routine.Delay(秒數)`、`yield return 子流程()`。
- **迭代器裡不能用指標**：碰遊戲記憶體的部分寫成一般的 `private static` 方法再呼叫。
- 開始時拿操作鎖（`Core.Lock.TryAcquire`），要用的核心能力借用（`Core.Talk.Acquire(Owner)`、`Core.Confirm.Register(...)`），停止時全部歸還。
- 支援暫停鍵：`Core.Paused` 時不推進。
- 等東西出現一定要有上限時間；逾時寫 log 並決定略過還是停止。

### Log 與訊息

- 每個功能用自己的 log：`FeatureLog.For("名稱")`，記每一步做了什麼、為什麼略過、失敗原因。出問題時請使用者給這個檔案。
- **給使用者看的訊息一律用 `Core/Notify`**，不要直接 `Services.Chat.Print`。每則都會記進「插件訊息」的紀錄，照用途選一種：
  - `Notify.Reply`：回應使用者打的指令（`/aetherkit …`），印在聊天欄。
  - `Notify.Info`：流程完成或停止、功能本身的輸出（已複製、選第幾條線），一般通知，幾秒後消失。
  - `Notify.Error`：按了開始但條件不符（「另一個自動流程正在執行」）、流程出錯停止，錯誤通知。
  - `Notify.Attention`：執行中要使用者處理才能繼續（「身上沒有野菜」「請切換採集模式」），通知不會自己消失。
  - 一般過程（開始了、每一步做了什麼）寫 FeatureLog，不要通知。

### 設定

- 新設定加在功能自己的 `*Config` 類別，給預設值。
- 算出來的唯讀屬性加 `[JsonIgnore]`。
- 模組的 `CopySettings` 要跟著加（匯入匯出用）。
- 設定只放真的需要使用者決定的；能有合理預設的就不要做成選項。

## 6. 新增功能的步驟

**模組（自動流程或功能）**
1. `Game/` 寫執行邏輯；`Modules/XxxModule.cs` 實作 `IModule`（自動流程設 `Group => ModuleGroup.Automation`）。
2. 設定類別加進 `Configuration`，`CopySettings` 補上。
3. `Plugin.cs` 的模組清單加一行；需要指令的在 `OnCommand` 加分支、說明文字補上。
4. 頁首、分頁照第 3 節。
5. 有改記憶體／遊戲函式就補改版檢查清單。

**小功能**
1. `Tweaks/Xxx.cs` 繼承 `Tweak`（在視窗清單上一件件處理的用 `LoopTweak`）。
2. 填 `Id`、`Name`、`Description`、`Group`、`Kind`、`Where`（出現在哪裡）。
3. 設定加在 `TweaksConfig`，選項畫在 `DrawSettings`。
4. 加進 `TweaksModule` 的清單。
